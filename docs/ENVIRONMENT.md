# متغیرهای محیطی

دو منبع مقدار وجود دارد:

1. **`.env.base44-defaults`** (در مخزن) — فقط پیش‌فرض‌های توسعه و جای‌نگهدارها.
2. **`/run/base44/app.env`** (بیرون از مخزن) — مقادیر واقعی/سری که پلتفرم تزریق می‌کند.

در `docker-compose.base44.yml` ترتیب `env_file` مهم است: فایل پیش‌فرض‌ها اول و فایل Secrets آخر
می‌آید، بنابراین مقدار واقعی همیشه برنده است. هیچ کلید حساسی نباید زیر `environment:` نوشته شود،
چون آن مقدار بر `env_file` اولویت دارد و جایگزینی بعدی را بی‌اثر می‌کند.

## ۱. متغیرهای اپلیکیشن

| نام | نیازمند بوت | توضیح |
| --- | --- | --- |
| `JWT_SECRET` | بله (توصیه اکید) | کلید امضای نشست. اگر تنظیم نشود، سرور کلید موقت می‌سازد و نشست‌ها با هر restart باطل می‌شوند. |
| `ADMIN_EMAIL` | خیر | ایمیل مدیری که در اولین بوت ساخته می‌شود. اگر تنظیم نشود، هیچ حساب مدیری ساخته نمی‌شود |
| `ADMIN_PASSWORD` | خیر | رمز همان مدیر. در `NODE_ENV=production` رمز جای‌نگهدار توسعه (`Hamrahan1404!`) و هر رمز کوتاه‌تر از ۱۲ کاراکتر رد می‌شود و حسابی ساخته نمی‌شود |
| `DEMO_MODE` | خیر | حالت نمایشی (نوار «نمونه‌کار نمایشی» + پرداخت شبیه‌سازی‌شده). فقط با `true` روشن می‌شود؛ در Production خاموش بمانید. مقدار تنظیم‌شده بر گزینه پنل مدیریت اولویت دارد |
| `DATABASE_URL` | بله | رشته اتصال PostgreSQL؛ در compose روی سرویس `db` تنظیم می‌شود |
| `UPLOAD_DIR` | خیر | مسیر فایل‌ها؛ پیش‌فرض `/app/uploads` |
| `PUBLIC_BASE_URL` | خیر | نشانی عمومی سایت برای canonical، نقشه سایت و callback درگاه |
| `PORT` | خیر | پورت API؛ پیش‌فرض `8000` |
| `NODE_ENV` | خیر | در توسعه `development`؛ روی سرور واقعی `production` (بررسی‌های امنیتی بوت و اعتبار رمز مدیر به آن وابسته است) |

## ۲. متغیرهای اختیاری درگاه پرداخت

| نام | توضیح |
| --- | --- |
| `PAYMENT_GATEWAY` | اگر `zarinpal` باشد و `PAYMENT_MERCHANT_ID` هم موجود باشد، پرداخت واقعی فعال می‌شود |
| `PAYMENT_MERCHANT_ID` | شناسه پذیرنده زرین‌پال |

بدون این دو، سایت در حالت **پرداخت شبیه‌سازی‌شده** کار می‌کند: هیچ مبلغی جابه‌جا نمی‌شود و نتیجه با
برچسب «پرداخت شبیه‌سازی‌شده» ثبت می‌گردد.

## ۳. متغیرهایی که پلتفرم تزریق می‌کند

| نام | مصرف‌کننده | توضیح |
| --- | --- | --- |
| `BASE44_PREVIEW_MODE` | `vite.config.js` | فقط با مقدار دقیق `"1"` دامنه sandbox به allowlist اضافه می‌شود |
| `BASE44_SANDBOX_HOST_DOMAIN` | `vite.config.js` | دامنه میزبان sandbox برای allowlist |
| `BASE44_PUBLIC_HOST_SUFFIX` | compose | ساخت `PUBLIC_BASE_URL` |
| `BASE44_PROJECT_ROOT` / `BASE44_CONFIG_ROOT` | compose | مسیر bind mount |
| `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS` | Vite | فهرست میزبان‌های مجاز اضافه |

هیچ‌کدام از این‌ها در کد سخت‌نویسی نشده‌اند؛ همه از محیط خوانده می‌شوند.

## ۳.۱ اطلاعات ورود آزمایشی (فقط sandbox)

`.env.base44-defaults` برای محیط توسعه/پیش‌نمایش Base44 مقدار
`ADMIN_EMAIL=admin@hamrahanomid.ir` و `ADMIN_PASSWORD=Hamrahan1404!` را دارد. این رمز جای‌نگهدار
توسعه است، در صفحه ورود نمایش داده نمی‌شود و در `NODE_ENV=production` پذیرفته نمی‌شود.
جزئیات استقرار واقعی در `docs/DEPLOYMENT.md`.

## ۴. افزودن یک متغیر جدید

1. نام آن را در `docs/` همین فایل و در `.env.base44-defaults` (اگر پیش‌فرض بی‌خطر دارد) اضافه کنید.
2. در compose، اگر سرویس به آن نیاز دارد، فایل Secrets یا `environment` مناسب را تنظیم کنید.
3. کد را طوری بنویسید که نبودِ مقدار باعث خطای مبهم نشود.

## ۵. بررسی حضور یک مقدار بدون دیدن آن

```bash
docker compose -f docker-compose.base44.yml exec -T api \
  sh -c 'printenv JWT_SECRET >/dev/null && echo present || echo missing'
```

هرگز مقدار Secrets را چاپ یا در لاگ ثبت نکنید.
